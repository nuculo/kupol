# 🧠 KAN → Duo-Agents: Вторая Волна Идей (Deep Index)

> **Источник:** Глубокий индекс 69 модулей `OCaml_KAN/lib/` и 22 архитектурных паттернов из Clojure KAN Research.  
> **Контекст:** Первые 4 идеи (Graph-KAN, MoE-Router, Temporal-KAN, Phi-Protocol) **уже реализованы** в Phase 9-12.

## 💡 Идея 5: Sparse Router (Инвертированный Индекс для OWASP)

**Исток:** `lib/kat/sparse_router.ml` — вместо плотного `Dense Matrix` маршрутизации, используется **Inverted Index** (Posting List). Эксперты набирают баллы только по активированным фичам, что даёт $O(K)$ вместо $O(N_{experts})$.

**Интеграция в Duo Agents:**
Наш текущий `MoeRouter` использует `if content.contains(...)` — это линейный поиск. Мы можем построить **Inverted Security Index**:
- Один раз при старте строим `HashMap<Keyword, Vec<PluginId>>`: ключевое слово → список плагинов, которым оно интересно.
- При сканировании файла мы токенизируем содержимое и делаем `lookup` в индексе. Каждый найденный токен добавляет баллы к соответствующим плагинам.
- Затем запускаем только `Top-K` плагинов по набранным баллам.
- **Результат:** Сканирование монорепо на 100к файлов за секунды, потому что маршрутизация стала $O(T)$ (по токенам), а не $O(F \times P)$ (файлы × плагины).

## 💡 Идея 6: Security Dropout (Randomized Fault Injection для Тестирования)

**Исток:** `lib/kan/dropout.ml` — случайное обнуление нейронов с вероятностью $p$ для предотвращения переобучения KAN-сети.

**Интеграция в Duo Agents:**
Вместо того чтобы всегда запускать **все** плагины (даже в режиме CI), мы добавляем режим **Security Dropout**:
- С вероятностью $p = 0.3$ случайный плагин "отключается" на один прогон.
- Если находки **исчезают** при отключении конкретного плагина → он действительно ловит реальные баги.
- Если находки **не меняются** → плагин дублирует другие и может быть удалён (Dead Plugin Detection).
- **Результат:** Автоматическая диагностика **качества** набора плагинов. Мы узнаём, какие плагины реально полезны, а какие — паразиты на CPU.

## 💡 Идея 7: DPO Loss (Preference Ranking для Приоритизации Уязвимостей)

**Исток:** `lib/optim/dpo_loss.ml` — Direct Preference Optimization, обучение модели через пары "хороший ответ vs плохой ответ" без explicit reward model.

**Интеграция в Duo Agents:**
Сейчас наш скоринг Risk Score — это жёсткий CVSS-подобный расчёт. Мы можем использовать DPO-подход для **обучения ранжированию**:
- Команда безопасности помечает пары: "Эта уязвимость более критична, чем вон та" (`chosen` vs `rejected`).
- Мы обучаем лёгковесную scoring function через DPO-Loss: $L = -\log\sigma(\beta \cdot (\Delta_{chosen} - \Delta_{rejected}))$.
- **Результат:** Risk Score адаптируется под конкретную организацию. Банк будет ранжировать SQLi выше, чем стартап, который ранжирует XSS выше. Персонализированный security scoring.

## 💡 Идея 8: Multi-Head Security Attention (KAT-Attention для Контекста)

**Исток:** `lib/kat/attention.ml` — Multi-Head Self-Attention с KAN-проекциями (Q, K, V через Group KAN вместо Dense Linear).

**Интеграция в Duo Agents:**
Наши плагины анализируют код **построчно**. Это слепой подход. Multi-Head Attention может дать нам **контекстное сканирование**:
- **Head 1 (Control Flow):** Анализирует поток управления (if/else, loops, returns) вокруг подозрительной строки.
- **Head 2 (Data Flow):** Отслеживает, откуда пришли данные в эту строку (taint tracking внутри функции).
- **Head 3 (Historical):** Использует историю изменений (git blame) для оценки "возраста" и "авторства" строки.
- Каждая "голова" генерирует свой вектор контекста, и финальный Score = `concat(H1, H2, H3) → OutProjection`.
- **Результат:** Плагин `unsafe_code` поймёт, что `unsafe {}` внутри `#[cfg(test)]` — это безопасно (Head 1 видит контекст тестов), а `unsafe {}` рядом с `extern "C"` в `core/` — это критично.

## 💡 Идея 9: Checkpoint/Resume для Долгих Сканов (Crash Resilience)

**Исток:** `lib/kan/checkpoint.ml` — сериализация весов KAN-модели через `Marshal` для восстановления обучения после крэша.

**Интеграция в Duo Agents:**
При сканировании огромных монорепо (10к+ файлов), CI runner может быть прерван по таймауту. Мы добавляем **Incremental Checkpoint**:
- Каждые N файлов сериализуем текущее состояние сканирования (список обработанных файлов + промежуточные findings) в `.duo-checkpoint.json`.
- При рестарте duo-agents проверяет чекпоинт и **продолжает с места остановки**, не пересканируя те же файлы.
- **Результат:** Гарантированное завершение сканирования даже на слабых GitLab Runner'ах с таймаутом 10 минут.

## 💡 Идея 10: Domain.spawn Parallelism (Multi-Core Actor Dispatch)

**Исток:** `lib/math/parallel.ml` — OCaml 5 `Domain.spawn` для параллельного вычисления KAN forward pass по батчам, с автоматическим определением количества ядер.

**Интеграция в Duo Agents:**
Наш текущий scan loop — **однопоточный** (`for file_path in &files`). Мы можем использовать Rayon (Rust аналог Domain.spawn) для **параллельного сканирования файлов**:
- `files.par_iter().flat_map(|f| scan_file(f))` — каждый файл сканируется на отдельном ядре CPU.
- MoE Router + Phi Engine остаются thread-safe (они stateless).
- **Результат:** На 16-ядерном CI runner'е сканирование ускоряется в ~12-14x (с учётом Amdahl's Law). Монорепо на 50к файлов за <5 секунд.

## 💡 Идея 11: Hybrid Symbolic Discovery (Автоматическое Создание Правил)

**Исток:** `hybrid_kan.clj` + `kan_symbolic.clj` — система пробует 11+ математических функций (sin, exp, log...) и, если $R^2 > 0.95$, **замораживает** числовой сплайн в точную символьную формулу (`FrozenPhi`).

**Интеграция в Duo Agents:**
Когда наш сканер несколько раз находит одну и ту же уязвимость в разных проектах, мы можем запустить **Symbolic Discoverer**:
- Собираем корпус найденных багов и их контекст (5 строк до/после).
- Discoverer пытается обобщить паттерн в **один регулярный шаблон** (символьное правило).
- Если точность шаблона $R^2 > 0.9$ (precision/recall на тестовых данных), он **замораживается** как новый `FrozenRule` и добавляется в плагин автоматически.
- **Результат:** Сканер сам "выращивает" новые правила из опыта, без ручного написания regex'ов.

## 💡 Идея 12: Agent KAN (ε-Greedy Мутация Правил)

**Исток:** `agent_kan.clj` — каждое ребро KAN действует как **автономный агент** с памятью и стратегией $\epsilon$-greedy, который может мутировать свои параметры.

**Интеграция в Duo Agents:**
Каждый OWASP плагин становится **агентом** с собственной стратегией:
- Плагин хранит *память*: какие паттерны давали True Positive, а какие — False Positive.
- С вероятностью $\epsilon = 0.1$ плагин **мутирует** свой набор правил (добавляет/удаляет regex).
- Успешные мутации (которые поймали новые баги без увеличения FP) закрепляются. Неуспешные — откатываются.
- **Результат:** Самоэволюционирующая система обнаружения, которая адаптируется к новым паттернам атак без обновления кода.
