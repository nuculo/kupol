# Зачем нам KAN в платформе Duo Agents? (Метод Фейнмана)

Давайте разберем это максимально простым языком, через понятные аналогии и без сухой математики.

## 🚰 Простая аналогия (Водопровод)

Представьте, что нейросеть — это сложная система водопроводных труб, цель которых — перелить воду из бассейна "Исходный код файла" в ведро "Здесь есть уязвимость".

**1. Как работают классические нейросети (MLP / Трансформеры):**
- У нас есть перекрестки (узлы). На каждом перекрестке стоит **фиксированный вентиль** (числовой "вес"), который мы крутим: пропускать больше или меньше воды. 
- Это работает классно, но чтобы решить сложную задачу, нам нужно построить лабиринт из миллиардов таких перекрестков. 
- **Проблема:** Это *"черный ящик"*. Если вода полилась в ведро "Уязвимость", мы не можем сказать **почему**. Вентилей так много, что для человека это просто белый шум чисел.

**2. Как работает KAN (Kolmogorov-Arnold Network):**
- В сетях KAN перекрестки тупые (просто суммируют воду), зато **умными становятся сами трубы** (ребра / connections). 
- Каждая труба сделана из гибкого материала (математический "сплайн"). При обучении труба *изгибается*, принимая идеальную форму для нужного потока воды. 
- **Результат:** Вместо миллионов перекрестков нам достаточно всего десяток умных труб.

## 🛡️ В чем смысл KAN конкретно для нашего сканера `duo-agents`?

Мы строим инструмент, который анализирует Merge Requests и ищет архитектурные дыры (Blast Radius, Trust Decay). Вот 3 причины, почему KAN — это геймчейнджер:

**1. Объяснимость (Explainable DevSecOps):**
Безопасникам и разработчикам не нужен ИИ-сканер, который говорит: *"Вероятность SQL-инъекции 98%, просто доверься мне"*. Разработчик пошлет такой сканер лесом (False Positives бесят всех).
Чудо KAN в том, что после того, как "умные трубы" приняли свою форму, их можно математически "свернуть" в **абсолютно понятную формулу**. KAN может сказать:
> *"Я поставил алерт, потому что: Если (пользовательская строка) складывается с (запросом к БД) БЕЗ (функции санитизации) = критический риск"*. 

Мы переводим магию нейросетей в прозрачный набор правил, который можно показать в Merge Request'е!

**2. Работа с графами (Architecture Graph):**
Полноценный анализ безопасности немыслим без визуализации связей (вкладка Architecture Graph в нашем Dashboard). KAN идеально ложится на графовые структуры. Гибкие сплайны на ребрах графа позволяют ИИ невероятно точно предсказывать, как "загнивание доверия" (Trust Decay) передается от одной уязвимой функции (`unsafe_unwrap`) вверх по цепочке вызовов прямо до API эндпоинта. 

**3. Анализ сложных паттернов на малом объеме данных:**
У нас нет триллионов строк кода с реальными архитектурными эксплойтами для обучения (хакеры не выкладывают в Open-Source свои лучшие атаки на микросервисы). Классическая нейросеть без биг-даты будет тупой. А KAN умеет "огибать" сложные логические функции гораздо эффективнее — он учится сложным архитектурным правилам на гораздо меньшем объеме примеров за счет гибкости своих функций на ребрах.

---

## 🎯 Резюме

Мы используем KAN в платформе, чтобы сменить парадигму. Вместо гигантского ИИ-"черного ящика", мы получаем **элегантный, быстрый и абсолютно прозрачный математический детектор**, который не только ловит сложные логические уязвимости в коде, но и может *доказать*, почему он считает это уязвимостью.
