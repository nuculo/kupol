# 🚀 Инфраструктура и Пайплайн (Pipeline & Infra)

Примитивы из Clojure `core.async` и паттерны высоконагруженных распределенных систем (Ring-Reduce), реализованные на Tokio в модулях `infrastructure` и `pipeline`.

## 1. Early Stopping & LR Finder

Модуль управления жизненным циклом и порогами:

- **Early Stopping (`early_stopping.rs`):** Если KAN-агент достигает уверенности в 99.9% на ранних этапах графа проверки (например, точное совпадение эксплойта), анализ обрывается досрочно (Actor Lease release), экономя CPU-часы кластера.
- **LR Finder (`lr_finder.rs`):** Механизм Leslie Smith's Learning Rate Finder адаптирован для авто-тюнинга Confidence Threshold. Перед каждым крупным MR сканер прощупывает оптимальный порог "строгости" проверок.

## 2. Распределенная координация и Ленивые вычисления

```mermaid
block-beta
    columns 3
    Lazy["Lazy DAG Выполнение"] Ring["Ring All-Reduce (Consensus)"] Stream["core.async (Streaming)"]
```

### Lazy DAG (`lazy_dag.rs`)
Атаки и проверки представлены в виде Directed Acyclic Graph (DAG). Если родительский узел проверки проваливается (например, "Это не SQL-запрос"), все сложные дочерние проверки на SQL-инъекции лениво сбрасываются из памяти.

### Ring All-Reduce (`ring_reduce.rs`)
Вместо того чтобы отправлять метрики от 60 распределенных Babylonian агентов в одну точку-агрегатор (что вызывает bottleneck), агенты передают частичные агрегации по логическому кольцу.
*Снижает сетевую нагрузку с `O(N)` до `O(1)` на узел.*

### Streaming `core.async` (`streaming.rs`)
Реализация скользящих окон (Sliding Window) над потоковыми каналами (Channels). Позволяет сканировать миллионы строк репозитория непрерывным потоком, удерживая в RAM только фиксированное N-количество AST-узлов. Конец OOM-ошибкам в CI/CD.
