# 🧬 Эволюционные Правила и NAS (Security Rules)

Модуль `security_rules` превращает статические правила анализа кода (grep / AST-patterns) в живые, самообучающиеся алгоритмы.

## 1. Evolutionary NAS (`evolution_nas.rs`)

Вместо того чтобы вручную подбирать веса для статических анализаторов (например, насколько подозрительна функция `eval` внутри цикла), запускается генетический алгоритм (Neural Architecture Search).

```mermaid
graph TD
    Pop[Начальная популяция правил (30 геномов)] --> Eval[Оценка на датасете MR]
    Eval --> Fitness{Расчет Физической пригодности (Fitness)}
    Fitness -- "Высокий False Positive" --> Penalize[Штраф]
    Fitness -- "Точное срабатывание" --> Reward[Награда]
    Penalize --> Select[Селекция Top 30%]
    Reward --> Select
    Select --> Cross[Crossover: Скрещивание параметров]
    Cross --> Mut[Mutation: Случайные изменения чувствительности]
    Mut --> Pop
```

## 2. LoRA-Adapted Rules (`lora_rules.rs`)

**Концепт:** Low-Rank Adaptation (LoRA), применяемая к статическому анализу кода.

1. **Frozen Base:** Матрица базовых эвристик жестко закодирована (заморожена) для гарантии того, что критические (OWASP Top 10) уязвимости всегда поймаются.
2. **LoRA Injection:** Под каждый проект (или даже под каждого разработчика) тренируются компактные матрицы (Low-Rank), которые "примешивают" локальную специфику к базовым весам.
3. **Результат:** Проект получает персонально-настроенный анализатор без перекомпиляции и переобучения тяжелого ядра базы правил.
